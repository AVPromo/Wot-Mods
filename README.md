# Stay Sharp — Medkit Reminder for World of Tanks

A small **client-side visual reminder** for the Commander's *Stay Sharp* perk.
When the perk allows using a ready medkit, an orange frame around its original HUD slot smoothly brightens for two seconds and fades for two seconds. No keypresses, automatic consumable use, game-stat changes, audio, or injected network traffic.

The mod uses the regular consumables HUD and works independently of arcade, sniper and SPG/strategic camera modes. It is packaged as **one `.wotmod`** containing the Python 2.7 game entrypoint and all required DDS frames.

## Downloads

**[GitHub Releases](../../releases/latest)** — download `com.staysharp.medkitreminder_<version>.wotmod` from the latest release. Only fully published Releases are downloadable; a failed draft is not a usable release.

## Installation

1. Close World of Tanks EU.
2. Remove every older `com.staysharp.medkitreminder_*.wotmod` from the active version folder.
3. Copy the downloaded `.wotmod` to `<World_of_Tanks_EU>/mods/<current_game_version>/`.
4. Start WoT. To uninstall, remove this single `.wotmod` file.

The version folder must match your currently installed WoT version. This modification is community-maintained and relies on internal WoT interfaces; **an update to WoT can break it**. The v1.5.0 rendering has been confirmed in a real client; the v1.6.1 event-driven implementation and the 1.6.1 log fix still require an in-game regression test. Back up the last working version before testing an update.

Diagnostic log (created on the player's computer, **never included in releases**): `%LOCALAPPDATA%\StaySharpMedkit\staysharp.log`.

## From source

Requirements: **Python 3.9+** for packaging/tests, no third-party Python libraries. The mod's embedded runtime remains **Python 2.7**, generated by the existing, verified bytecode bootstrap.

```sh
python3 -m unittest discover -s tests -v
python3 scripts/privacy_audit.py
python3 source/build_wotmod.py
sha256sum dist/*.wotmod
```

The `assets/medkit_pulse_master.dds.b85` file is a compressed, ASCII-encoded source DDS. The builder recreates **all 21 original DDS animation frames byte-for-byte** using an exact, tested alpha-scaling formula; the full assets do not need to be separately committed. The **historical v1.6.0** artifact has SHA-256 `9f3d98948ed398c3a4dc14b6785b68f10f1319381f896c6cd49b8709359c4927`. This legacy check applies only when building v1.6.0. Current code starts at **v1.6.1**, which includes a Windows log-rotation fix.

See [build and release documentation](docs/BUILD_RELEASE.md), [technical notes](docs/REVIEW_1.6.0.md), and [installation guide](docs/INSTALACJA.md).

## Changes, reviews and releases

1. Submit a PR to `main`. GitHub Actions runs unit tests, privacy checks and a deterministic build with **read-only** repository permissions.
2. After review and merge, GitHub Actions builds and validates the `.wotmod`, transfers the verified files to a separate **write-scoped publishing job** using official `actions/upload-artifact` / `download-artifact`, and creates a GitHub Release with official `gh release create`.
3. Every new push to `main` produces a unique patch version derived from the Release workflow run number. Retrying a successful run verifies the existing release without overwriting it; a failed run can leave a gap in release numbers.

No custom HTTP client, third-party publication service or Java is involved; GitHub's own CLI and built-in `GITHUB_TOKEN` handle the release. Neither the workflow nor a separate recovery script deletes an existing Release. If publication is interrupted, check the draft manually; the pipeline fails safely instead of guessing what to remove.

The historical first run created an empty **draft `v1.6.1`**. It is not public as a downloadable release and does not prevent the next distinct build (expected `v1.6.2`). Before merging the simplified release workflow, enable **Settings → Releases → Enable release immutability** for future published assets and tags. See [build and release documentation](docs/BUILD_RELEASE.md).

**Mandatory protection before merge:** enable the active GitHub tag
ruleset `wotmod-release-tags` for `v*`, with **Restrict updates**, **Restrict
deletions**, and **no bypass actors**. Without it, the publishing workflow
intentionally stops **before creating a tag or Release**. Details:
[required release-tag protection](docs/BUILD_RELEASE.md#required-github-tag-protection-before-merging).

## Privacy and safety

No player ID, nickname, account token, email, API key, machine identifier, private path, telemetry collector or crash dump is shipped in source or releases. The build process scans for common secret/PII patterns. This does **not** anonymize commit author/committer names or prior PR/Actions activity. Runtime logging is local-only and is never uploaded by the mod.

As the repository is **public**, the **GitHub account that owns it, commits, PRs, Release authorship, Actions history and logs** will be publicly attributable; this repository cannot conceal its GitHub owner's identity. Do not commit private test logs or screenshots. See [publication checklist](docs/PUBLICATION_PRIVACY.md).
